# СметаБыстро — MVP

Реализация по документу «Архитектура и техническое задание "СметаБыстро"»
(сентябрь 2026). Это демонстрационный MVP для пилота, а не продакшен-система —
см. раздел «Важные допущения и упрощения» ниже.

## Запуск (демо на локальном ПК, раздел 2.1 ТЗ)

Управление зависимостями — через [uv](https://docs.astral.sh/uv/): один
инструмент вместо venv+pip, версии и хеши всех пакетов зафиксированы в
`uv.lock`, установка кэшируется и работает намного быстрее pip.
Рекомендуется Docker/WSL2 — WeasyPrint зависит от нативной библиотеки Pango,
которую сложнее ставить на «голом» Windows.

```bash
cd backend

# uv сам создаст .venv и поставит зависимости строго по uv.lock
uv sync

# (опционально) вручную импортировать/обновить базу цен:
uv run scripts/import_prices.py

uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Если `uv` ещё не установлен: `pip install uv` или
`curl -LsSf https://astral.sh/uv/install.sh | sh` (см. официальную
документацию для вашей ОС).

Открыть `http://localhost:8000` в браузере. При первом запуске база цен
подхватится из `data/prices.csv` автоматически (см. `AUTO_SEED_ON_STARTUP`
в `app/config.py`) — вручную запускать `import_prices.py` нужно только при
последующих обновлениях цен.

Для внешнего доступа с телефонов бригад — Cloudflare Tunnel поверх этого же
процесса (раздел 2.1 ТЗ), в этот код не входит и настраивается на уровне ОС:

```bash
cloudflared tunnel --url http://localhost:8000
```

## Запуск через Docker (рекомендуется на Windows, раздел 2.1 ТЗ)

Снимает проблему с нативными библиотеками WeasyPrint (Pango) на «голом»
Windows — весь код и системные зависимости уже внутри образа.

### Dockerhub

Для быстрого деплоя образ опубликован в Dockerhub.
Скачивание и запуск готового образа:
```sh
docker run -p 8000:8000 -v smetabystro_storage:/app/backend/storage jwth32/smeta_bystro:v1
```

### Локальная сборка

```bash
docker compose up -d --build
```

Открыть `http://localhost:8000`. База цен из `data/prices.csv` подхватится
автоматически при первом запуске. `db.sqlite3` и PDF-файлы хранятся в
именованном томе `smetabystro_storage` — они переживут `docker compose down`
и пересборку образа, но **не** отдельную резервную копию: файл БД всё равно
нужно копировать наружу вручную (см. пункт 6 ниже и комментарий в
`docker-compose.yml`).

Обновить базу цен внутри уже запущенного контейнера:

```bash
docker compose exec smetabystro uv run scripts/import_prices.py
```

## Важные допущения и упрощения (прочитать перед использованием)

1. **Аутентификация — не настоящая.** Вход по номеру телефона без кода
   подтверждения (`app/security.py`). Любой, кто знает номер, может зайти
   под чужим аккаунтом. Это осознанный риск для пилота на 5–10 лично
   известных бригад (раздел 1.1 ТЗ), а не недоработка — но для реальной
   эксплуатации это нужно заменить на полноценный SMS/OTP или иной механизм.

2. **Длина/ширина ската трактуются как горизонтальная проекция**, поэтому
   формула `площадь / cos(угол)` в `calculator.py` корректно даёт площадь
   по уклону. Если бригадиры на пилоте будут вводить длину, измеренную
   рулеткой **по самому скату**, это даст завышение — см. предупреждение
   в докстринге `calculator.calculate_roof`. Это ровно то, что нужно
   проверить на 3 реальных объектах в день 2 плана (раздел 4 ТЗ).

3. **Расчёт стоимости работ** (`estimation.py`) — прозрачная, но
   самостоятельно выбранная формула (расценка × площадь для единицы "m2",
   расценка × периметр для "m", расценка за проект для прочих единиц).
   Пример в разделе 3.1 ТЗ не позволяет однозначно вывести формулу из
   приведённых чисел — при передаче кровельщику стоит явно согласовать
   этот момент.

4. **Одна кровля = один скат** в форме фронтенда (`measurements.html`) —
   для MVP-демонстрации. Бэкенд (`CalculateRequest.slopes`) уже принимает
   список скатов, расширение формы на несколько скатов не требует
   изменений API.

5. **`accessories_sku` в API оставлен для совместимости** с примером
   запроса из ТЗ, но фактически не используется: крепёж, обрешётка,
   водосток и планки примыкания считаются калькулятором автоматически по
   нормативам (`roof_norms.json`), а не выбираются пользователем вручную.

6. **Резервное копирование не автоматизировано** (раздел 2.1 ТЗ) — файл
   `backend/storage/db.sqlite3` нужно копировать на внешний диск/облако
   вручную, автоматики в этом MVP нет.

7. **WorkRate как таблица** не задействована через API в этой версии —
   расценки передаются в каждом запросе на расчёт, а не сохраняются и
   переиспользуются. Модель оставлена в `models.py` под будущее развитие.
